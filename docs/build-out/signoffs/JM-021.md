## STATUS: PARTIAL — FLOW_BUG (RC-7 PERSISTS, App engineer + QA)

The full recovery chain (login → forgot → recover → verify) still reaches the verify-code
screen with every upstream step complete. The Run 2→3 fix added per-cell Semantics IDs
(`verify_code_input_0..5`) to `OmdsOtpInput`, and Maestro's `tapOn id: verify_code_input_N`
now resolves/taps the cells (confirmed via hierarchy) — but RC-7 **persists**: `inputText`
after the tap does NOT set the underlying `TextField` value (post-run hierarchy shows all
cell text attributes empty). The Semantics node is a `container:true textField:true` wrapper,
not the editable leaf, so Android Accessibility text injection does not descend into the inner
`TextField`. `state.code` never reaches 6 chars, `submit()` stays guarded, and the chain never
advances to `/set-password`. QA confirms the mock recovery code is NOT consumed — the API was
never called. This is still a test-harness/widget-addressability interaction bug, not a screen
defect; it now needs an app-engineer widget change (the per-cell-id-only approach was
insufficient).

### Exact failing AC + QA category

- **Failing AC:** **AC1** (and AC2/AC3 blocked by the same multi-cell input bug). First failing step: `Assert id: setpw_new_field is visible`.
- **QA failure category:** **FLOW_BUG** (`61_W0_QA_RESULTS.md` Run 3 row jm-021).
- **Root cause (RC-7 PERSISTS):** per-cell Semantics IDs landed and are tappable, but each cell
  is a `Semantics(identifier, container:true, textField:true, child: ...TextField...)` wrapper.
  `tapOn` focuses the container, not the leaf `TextField`; Android `inputText` injects to the
  innermost editable node, which is not the focused container — so cells stay empty. Confirmed
  by post-run hierarchy (all cell text `""`) and the un-consumed mock recovery code.

### Owner action to close

1. **App engineer, P1 — low effort (widget, the per-cell-id approach was insufficient):** make
   each cell's `TextField` the Semantics **leaf**, not a wrapped child. Either:
   - give each cell's `TextField` a `key: Key('${identifier}_$index')` and drop the wrapping
     Semantics container (Maestro can target by the resource-id derived from the key), OR
   - use `Semantics(identifier: '${base}_$index', child: TextField(...))` with the TextField as
     the direct child and `ExcludeSemantics`/`MergeSemantics` so the editable node IS the
     addressed node.
2. **QA, P1 — alternative within current widget:** try Maestro child indexing
   `tapOn: { id: "verify_code_input", index: N }` to focus the Nth editable cell directly.
3. **Preferred (dev-seam bypass, App engineer):** add a `jeeb.route=/recover/verify?preset_code=654321`
   dev-seam deep-link that pre-fills the verified-code state so the test reaches `/set-password`
   without interacting with OTP cells. This is a **joint App engineer + QA** fix shared with jm-022.
