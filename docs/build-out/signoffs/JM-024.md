**PO grounding (source-checked):** the route IS registered — `app_router.dart` l.667-671 registers
`name: 'settings-addresses'` → `SavedLocationsScreen()` at `/settings/addresses`, and
`client_location_screen.dart` l.243 correctly calls `context.pushNamed('settings-addresses')`. The
screen file `saved_locations_screen.dart` l.153 sets `identifier: 'saved_address_add_cta'`. So this
is **NOT a missing route and NOT a missing id in code** — the CTA is simply not being rendered in
the state the screen reaches on-device (most likely the screen renders a loading/empty/error state
because the `jeeb.seam.journey=has_saved_addresses` seed does not seed the saved-locations mock
fixture the screen reads, or the CTA is gated behind a non-empty list). Shared root cause with
JM-049 / JM-050.
