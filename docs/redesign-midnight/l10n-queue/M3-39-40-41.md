One key is **required**, on M3-40 only. M3-39 and M3-41 needed no new copy: both
already own a headline that states an absence, and both now print it exactly
once (the duplicated bar title was deleted, not re-worded).

## 1. `requestSummaryUnavailableHeadline` (REQUIRED)

Call site: `RequestSummaryUnavailableScreen`, the `JeebEmptyState` under the
frozen `Key('request-summary-unavailable-state')`.

`requestSummaryUnavailableTitle` resolves to **"Review & submit"** — a screen
NAME, not a statement of absence. That was tolerable while it sat on an app bar
above a separate note. It is wrong as the empty block's `h1`, because the
headline is now the first and largest thing on the screen and it announces the
draft-review surface that is precisely what is missing. Its two siblings say
"Request no longer available" and "Profile unavailable"; this one says
"Review & submit" over an empty box.

The body key is already correct and stays: `requestSummaryUnavailableBody` —
*"No request draft available. Start a new request to continue."*

**Nearest existing key in use meanwhile:** `requestSummaryUnavailableTitle`
itself, tagged `TODO(midnight): l10n-queued` at the call site. Swapping in
another domain's absence string ("Request no longer available") would be worse:
it names a *request* that expired, when nothing was ever submitted here.

Rejected: reusing `requestUnavailableTitle` (wrong noun, see above) and
`clientHomeEmptyTitle` (invites a new request, which is the BODY's job here and
would print the same instruction twice).

## 3. Nothing queued for M3-41

instruction off the bottom. The bar title is gone, so the string prints once.
