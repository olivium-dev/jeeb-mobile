# l10n queue — M3-30 · support-ticket

**The restyle itself needed ZERO new keys**, and no `TODO(midnight):
l10n-queued` marker was planted: every string on the screen is a pre-existing
key, and no site renders a Midnight-invented stand-in. The two phase views that
moved onto `JeebEmptyState` reuse the headlines they already rendered
(`escalateSubmitting`, `escalateErrorNetwork` / `escalateErrorServer`) and pass
no `body:`, so no second line had to be invented.

## What the captures DID prove — the category pills expose a copy collision

The screen has carried nine `l10n KEY REQUEST` comments since JM-063 (dedicated
`supportCategory*` / `supportAttach*` / `supportError*` keys were requested in
`50_ROUTE_REQUESTS.md` and never written), and every visible label is a reused
key. That was tolerable while the picker was a radio list nobody had rendered
side by side. The Midnight pill group renders **all** options at once, and the
capture makes two collisions plain:

`docs/redesign-midnight/captures/M3-30/…__0-form-empty-nothing-selected-yet.png`

| Site | Key today | Renders |
|---|---|---|
| band header | `customerProfileSectionSupport` | **SUPPORT** |
| category `account` | `customerProfileSectionSupport` | **Support** |
| category `dispute` | `disputeStatusSupportCta` | **Contact support** |
| screen title | `supportTitle` | **Contact support** |

So the band header and its own first pill say the same word, and one pill
repeats the screen title verbatim. A user choosing "Contact support" from
inside *Contact support* has no way to know it means "a dispute".

Proposed keys (AR strings are proposals, not translations of record — the l10n
lane owns the final wording):

| Key | EN | AR | Site |
|---|---|---|---|
| `supportCategoryLabel` | `What's this about?` | `عن ماذا تسأل؟` | `_CategoryField` band header — today `customerProfileSectionSupport`. |
| `supportCategoryAccount` | `My account` | `حسابي` | category `account` — today `customerProfileSectionSupport`. |
| `supportCategoryPayment` | `Payments & earnings` | `المدفوعات والأرباح` | category `payment` — today `navEarnings`. |
| `supportCategoryDelivery` | `A delivery` | `طلب توصيل` | category `delivery` — today `navDelivery`. |
| `supportCategoryKycAppeal` | `Appeal a KYC decision` | `الاعتراض على قرار التحقق` | category `kycAppeal` — today `kycRejectedAppealCta`. |
| `supportCategoryDispute` | `A dispute` | `نزاع` | category `dispute` — today `disputeStatusSupportCta`. |
| `supportCategoryOther` | `Something else` | `شيء آخر` | category `other` — today `escalateReasonOther`. |

## Second finding — the retry CTA says "Submit"

`support_retry_cta` reuses `supportSubmitCta` (**Submit**) with a refresh glyph,
under the network-error headline "*Your report will be retried automatically*".
The button reads as a fresh submit of a report the sentence just said is already
queued. Visible in `…__4-error-network-failure.png`.

| Key | EN | AR | Site |
|---|---|---|---|
| `supportRetryCta` | `Try again` | `حاول مرة أخرى` | `_ErrorView` `support_retry_cta` — today `supportSubmitCta`. |

## Not blocking, not proposed here

The remaining reuses read correctly and are left alone: `escalateCommentLabel`
(body field), `ordersTitle` (order-link field), `escalatePhotoLabel` /
`photoAttachmentAddLabel` (attachments), `escalateConfirmation*` (the
confirmation copy — same "we received it" semantics as the dispute twin).
