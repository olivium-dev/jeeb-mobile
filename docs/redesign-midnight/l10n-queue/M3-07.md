# l10n queue — M3-07 · Customer profile tab

Three keys. They exist because M3-07 gives the screen a **loading** and an
**error** state it never had (the cubit has recorded `status`/`error` since
JM-035; nothing rendered them). Every other string on the screen already exists
in both catalogs.

Verified against `lib/l10n/app_en.arb` / `app_ar.arb` on 2026-08-04.

| Key | EN | AR |
|---|---|---|
| `customerProfileLoadingHeadline` | `Loading your profile` | `جارٍ تحميل ملفك` |
| `customerProfileLoadErrorTitle` | `Couldn't load your profile` | `تعذّر تحميل ملفك` |
| `customerProfileLoadErrorRetry` | `Retry` | `إعادة المحاولة` |

## 1. `customerProfileLoadingHeadline`

There is already a shipped **"Loading your …"** family —
`activeDeliveryLoadingHeadline` ("Loading your delivery"),
`earningsLoadingHeadline` ("Loading your earnings"),
`orderHistoryLoadingHeadline` ("Loading your orders"). This is its profile
member; the family exists precisely so each surface names its own noun.

Call site (currently on the fallback): the `JeebEmptyStateStatus.loading`
headline in
`lib/features/customer_profile/presentation/widgets/customer_profile_status_block.dart`.

**Nearest existing key in use meanwhile:** `customerProfileTitle` ("Profile").
Chosen because it is the screen's own name and therefore cannot say anything
false; every other candidate carries another surface's noun ("your earnings",
"your orders"), which would be a visible lie rather than a placeholder. The
breathing skeleton carries the "loading" meaning until the key lands.

## 2. `customerProfileLoadErrorTitle`

Same shape as the shipped `homeLoadFailedTitle` / `orderHistoryErrorTitle` /
`requestFeedErrorTitle` trio — one per surface, each naming its own noun.

Call site: the `JeebEmptyStateStatus.error` headline in the same file.

**Nearest existing key in use meanwhile:** `requestSummaryErrorGeneric`
("Something went wrong. Please try again.") — the only noun-free error string in
the catalog, so it is honest on this surface. `homeLoadFailedTitle` was rejected:
"Couldn't load your home" on the Profile tab is wrong copy, not placeholder copy.

## 3. `customerProfileLoadErrorRetry`

**Nearest existing key in use meanwhile:** `homeLoadFailedRetry` ("Retry") — the
value is already textually identical, so this key is convention-only (the ARB
convention here is one key per surface; 15 identical "Retry"/"Try again" keys
already ship). Land it with the other two or drop it — the call site is correct
either way.

## Deliberately NOT queued

- **No error-body key.** The error block ships headline + Retry with no body:
  the two candidate bodies (`homeLoadFailedBody`, `requestSummaryErrorNetwork`)
  both end in "try again", which the Retry pill already says. If a body is
  wanted later it should be typed off `CustomerProfileFailure`
  (`network` / `unauthorized` / `unknown`), which is a copy decision, not a
  wiring gap.
- **An "empty profile" string.** There is no empty state to name: the identity
  card falls back to the shipped `profileNamePlaceholder` ("Add your name"),
  which is exactly what `settings_identity_card.dart` — R22's measured twin —
  already ships for the same null.
- `customerProfileLanguage` / `customerProfileRating*` — still open from
  pass-1's `50_ROUTE_REQUESTS.md`, unchanged by this row, and Maestro keys on the
  identifiers rather than the text.
