# l10n queue — M3-28 saved addresses · M3-29 address detail form

Four new strings across the pair. All four exist because the Midnight §2.7
state family needs a **headline** where the OMDS surfaces they replace needed
none (`OmdsLoadingState` took no copy at all; `OmdsErrorState` took one
sentence and drew it as body).

Verified against `lib/l10n/app_en.arb` / `app_ar.arb` on 2026-08-04.

| Key | EN | AR |
|---|---|---|
| `savedAddressesLoadingHeadline` | `Loading your addresses` | `جارٍ تحميل عناوينك` |
| `savedAddressesErrorHeadline` | `Could not load saved locations` | `تعذّر تحميل المواقع المحفوظة` |
| `savedAddressesErrorBody` | `Please try again.` | `حاول مرة أخرى.` |
| `addressFormLoadingHeadline` | `Opening the address form` | `جارٍ فتح نموذج العنوان` |

## `savedAddressesLoadingHeadline`

Member of the shipped "Loading your …" family — `activeDeliveryLoadingHeadline`,
`earningsLoadingHeadline`, `orderHistoryLoadingHeadline`,
`customerProfileLoadingHeadline`, `notificationsLoadingHeadline`,
`walletActivityLoadingHeadline`, `txnDetailLoadingHeadline`.

Not `savedAddressesTitle` ("Saved addresses") — `orderHistoryLoadingHeadline`'s
own ARB description pins the rule: *must not repeat the header band's own
title*. The noun may repeat (`notificationsLoadingHeadline` = "Loading
notifications" against a "Notifications" title); the whole title may not.

Call site: `_LoadingView` in
`lib/features/location/presentation/saved_locations_screen.dart`.

## `savedAddressesErrorHeadline` / `savedAddressesErrorBody`

**Not new copy.** These are the shipped `savedLocationsError` sentence split at
its own full stop, in both locales, so the §2.7 error block gets a headline and
a body:

- EN `Could not load saved locations. Please try again.`
- AR `تعذّر تحميل المواقع المحفوظة. حاول مرة أخرى.`

Nothing invented, nothing dropped. Same move the M3-22 lane made with
`accountStatusLoadError`. `savedLocationsError` itself stays — it is still the
snackbar/other-surface string.

## `addressFormLoadingHeadline`

The gate this names is the **session read** (`AuthTokenStore.userId`) that
`AddressDetailFormScreen` mounts a `FutureBuilder` on; it is not a fetch of the
address, so "Loading your address" would be a lie on the add path (there is no
address yet). "Opening the address form" names the act truthfully, in the same
register as `accountStatusLoadingHeadline` ("Checking your account"), which is
the precedent for a non-"Loading" verb where the read is not a list fetch.

Not `addressFormTitle` ("Address details") — header-band rule again.

Call site: `_SessionResolveGate` in
`lib/features/location/presentation/screens/address_detail_form_screen.dart`.

The five `AddressFormL10n` field labels became **more** visible in M3-29: they
moved from `OmdsTextField.labelText` (a floating Material label) to a
`JeebSectionLabel` band header, so they now render uppercase and never
disappear once the field is filled. `JeebSectionLabel` exempts `ar` from the
case transform, so the Arabic run is unaffected.

## Deliberately NOT queued

- **A category-picker label set.** `savedLocationsChipHome` / `…ChipWork` /
  `…ChipOther` already exist in both locales, but M3-29 does **not** mount a
  category control — see the open question in the row report. Queuing copy for a
  control nobody has ruled on would be inventing the feature sideways.
- **A "no pin" error string.** `AddressFormL10n.pinMissing` already says exactly
  what the empty coordinate row needs to say, and it was already the block's
  `Semantics.label`. Reused, not duplicated.
