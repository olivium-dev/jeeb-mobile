# l10n queue — M3-22 · Account status (suspended / locked)

One new string. It exists because M3-22 replaces `OmdsLoadingState` with the
Midnight empty family, and `JeebEmptyState` requires a headline where a bare
spinner needed none.

Verified against `lib/l10n/app_en.arb` / `app_ar.arb` on 2026-08-04.

| Key | EN | AR |
|---|---|---|
| `accountStatusLoadingHeadline` | `Checking your account` | `جارٍ التحقق من حسابك` |

## `accountStatusLoadingHeadline`

Member of the shipped "Loading your …" family —
`activeDeliveryLoadingHeadline`, `earningsLoadingHeadline`,
`orderHistoryLoadingHeadline`, `customerProfileLoadingHeadline`,
`notificationsLoadingHeadline`, `otpHandoverLoadingHeadline` ("Getting your
code" — the family already tolerates a non-"Loading" verb where it reads
better). "Checking" is that verb here: the read resolves *which* blocked state
the account is in, it does not fetch a list.

Call site: the `JeebEmptyStateStatus.loading` headline in
`lib/features/account_status/presentation/account_status_screen.dart`
(`_LoadingBody`).

**Where it renders from meanwhile:** `AccountStatusL10n.loadingHeadline`, an
inline EN/AR getter in
`lib/features/account_status/presentation/account_status_l10n.dart`, tagged
`TODO(midnight): l10n-queued`.

**Why inline rather than the usual "nearest existing key with a TODO":** every
candidate is a visible lie rather than a placeholder, and this feature already
ships its own copy outside the ARB (see below), so the inline form is this
file's existing convention rather than a new mechanism.

- `accountStatusTitle` ("Account unavailable") — the header band already draws
  it two rows above. `orderHistoryLoadingHeadline`'s own ARB description pins
  this as a rule: *"must not repeat the header band's own title"*.
- `customerProfileLoadingHeadline` ("Loading your profile") — same `GET
  /users/me` wire, wrong noun on a blocked-account surface.
- Every other family member names another surface's noun.

## Already inline, NOT introduced by this row

`AccountStatusL10n` has shipped four members outside the ARB since W4 —
`banner()`, `defaultReason()`, `loadError`, `retry`. Flagging them here so the
ARB lane sees the whole surface, not just the one string M3-22 added:

| Member | EN | AR |
|---|---|---|
| `banner(suspended)` | `Your account is suspended` | `تم تعليق حسابك` |
| `banner(locked)` | `Your account is locked` | `تم قفل حسابك` |
| `defaultReason(suspended)` | `Your account is under review. Contact support to resolve it, or sign out.` | (present) |
| `defaultReason(locked)` | `Your account has been locked for security. Contact support to restore access, or sign out.` | (present) |
| `loadErrorTitle` | `Couldn't load your account status` | `تعذّر تحميل حالة الحساب` |
| `loadError` | `Check your connection and try again.` | `تحقّق من اتصالك وحاول مجددًا.` |
| `retry` | `Retry` | `إعادة المحاولة` |

`loadErrorTitle` / `loadError` are **not new copy**: M3-22 split the one shipped
sentence at its own full stop so the error block gets a headline and a body.
Nothing was invented and nothing dropped, in either locale.

## Deliberately NOT queued

- **An empty-state string.** This screen has no empty state to name. The cubit's
  machine is `initial | loading | loaded | failed`, and `AccountStatusValue` is a
  closed `{suspended, locked}` whose `fromWire` defaults to `suspended` — a
  loaded body can never be blank. The nearest thing is "loaded with no server
  reason", which already falls back to `defaultReason(value)`.
- `accountStatusBody` (`accountStatusBody` / `AccountStatusL10n.genericBody`) is
  still unreferenced, as it was before this row. It predates the per-state
  `defaultReason` copy that superseded it. Deleting it is an ARB-lane call.
