# l10n queue — M3-24 · notification-prefs

The restyle needed **two** new keys, both for states that did not previously
exist as designed surfaces: the cold read and the failed cold read now mount
`JeebEmptyState` (kit ruling 1), which takes a headline the screen never had.

Both sites ship today on the nearest existing locale-safe key, marked in source
with `TODO(midnight): l10n-queued`. Neither reads *wrong* — they read as the
notifications **inbox** rather than the notification **preferences** — so this
is copy-polish, and no AC or Maestro flow asserts visible text here.

| Key | EN | AR | Site (today's stand-in) |
|---|---|---|---|
| `notificationPrefsLoadingHeadline` | `Loading your preferences` | `جارٍ تحميل تفضيلاتك` | `notification_prefs_screen.dart` `_LoadingView` — today renders `notificationsLoadingHeadline` (`Loading notifications`). |
| `notificationPrefsErrorTitle` | `Couldn't load your preferences` | `تعذّر تحميل تفضيلاتك` | `notification_prefs_screen.dart` `_ErrorView` headline — today renders `notificationsErrorTitle` (`Couldn't load notifications`). |

The AR strings are proposals, not translations of record — the l10n lane owns
the final wording. Both follow the house convention already used by
`walletActivityLoadingHeadline` / `walletActivityErrorTitle`,
`txnDetailLoadingHeadline` / `txnDetailErrorTitle`,
`customerProfileLoadingHeadline` / `customerProfileLoadErrorTitle`.

The error **body** needs nothing: `notificationPrefsLoadError`
("Couldn't load your notification preferences.") is dedicated copy and already
ships in both locales. Title reads generic, body reads precise.

## Pre-existing, carried forward unchanged (JM-058 CTO-D R-F)

Three sites on this screen were already reusing a near-miss key before Midnight,
and M3-24 did not disturb them. Re-listing so the l10n lane can close them in
one pass rather than discovering them a third time:

| Want | Today's stand-in | Site |
|---|---|---|
| a push-channel note ("These are push notifications…") | `notificationPreferencesRowSubtitle` (`Manage what you get notified about`) | `_PushOnlyNote` |
| a transactional-locked label | `notificationCategoryOtp` (`Security codes`) | `_TransactionalLockedRow` title |
| a transactional-locked sub | `notificationCategoryOtpAlwaysOn` (`Always on so you can sign in`) | `_TransactionalLockedRow` subtitle |

R22 renders the same locked row as one line via `settingsAlwaysOnQualifier`
(` · always on`). M3-24 deliberately keeps two lines — see the report's
selfCritique — so the two screens legitimately consume different keys for the
same board object. If the l10n lane would rather they converge, the M3-24 site
is the one to change.
